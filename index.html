Live visualization transition

A small grammar for change.

Visualization states are declarations. A delta describes what changed. A transition evaluates that change at a normalized progress value.

Visualization bar().data(rows).x("country").y("sales") is an immutable declaration of one chart state.
Delta The runtime compares two resolved, same-idiom visualizations. The controller exposes the result as change.delta for inspection.
Transition transition(from, to) creates a seekable controller with progress(), play(), pause(), and lifecycle methods.
Driver and composition Buttons, sliders, timers, and scroll supply progress. seq() and story() compose more than two states when needed.
Pair transition API 
import { bar } from "scrollylite/bar";
import { transition } from "scrollylite/transition";

// Two declarations, one shared source
const sales = bar()
  .data(rows)
  .x("country")
  .y("sales")
  .key("country");

const profit = sales.y("profit");

// Compile once, then evaluate any frame
const change = await transition(
  sales, profit,
  { target: "#vis", d3 }
);

change.progress(0.37);
change.play({ duration: 800 });

The transition is the core.

Scroll is one possible driver. Narrative text, sequences, and page layout are optional composition layers around the same evaluator.

Canonical terminology
  1. Visualization: an immutable declarative endpoint.
  2. Delta: the resolved difference between two endpoints.
  3. Transition: an executable mapping from progress to frame.
  4. Progress: a normalized value from 0 to 1.
  5. Driver: an event, timer, gesture, or scroll position that supplies progress.
  6. Composition: an optional Sequence or Story around multiple visualizations.
Current scope
core:
  visualization: bar | line | point | unit
  transition: same-idiom endpoints only
  evaluation: play | pause | progress

semantic_change_classes:
  - focus
  - guide
  - granularity
  - observation

composition:
  sequence: seq()
  story: story() + render()
  standalone_sequence: chart()

deferred:
  - cross-idiom transitions

Compose more than two states.

A sequence orders visualization declarations. Each adjacent pair is still interpreted as a transition between two endpoints.

Drive the same transition your way.

Use play() for time-based motion or progress(p) for direct frame evaluation. Scroll is an adapter, not a requirement.

Discrete

change.play()

A click, keyboard command, route change, or timer can play the transition forward or backward. 

const change = await sl.transition(
  vertical, horizontal,
  { target: "#chart", d3, aq }
);

let reversed = false;
btn.onclick = () => {
  change.play({
    from: reversed ? 1 : 0,
    to: reversed ? 0 : 1
  });
  reversed = !reversed;
};

Slider

change.progress(p)

A slider, gesture, or scroll adapter can display any normalized frame directly, in any order. 

// Same endpoints, direct frame evaluation
const change = await sl.transition(
  vertical, horizontal,
  { target: "#chart", d3, aq }
);

// slider min=0, max=1, step=0.01
slider.oninput = () =>
  change.progress(+slider.value);

Current capabilities

What the code supports today.

This page demonstrates the 0.2.0 release candidate, not a published CDN version. The statements below describe this source checkout.

VIEW

Immutable declarations

Chain data, encodings, filters, identity, and idiom operations. Deriving a state preserves its source state.

4

Four built-in idioms

Bar, line, point, and unit share the core encoding, filtering, keying, and tooltip vocabulary.

Δ

Semantic delta classes

Changes can be classified as focus, guide, granularity, or observation. Idiom support varies by class.

t

Seekable evaluation

Bar transitions cache compiled frames. Line, point, unit, and custom idioms currently use deterministic reconstruction.

API

Optional composition

Use a pair directly, organize states with seq(), or mount a complete scrolling story with render().

CSS

Tokens and plugins

Custom runtime idioms register with registerChartModule({ plugin }). Package theme entries include Default, Dark, and Paper. Warm remains a legacy source alias.
